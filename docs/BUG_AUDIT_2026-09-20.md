# Story Teller — offline bug audit

Date: 2026-09-20. Scope: application audit only; no application fixes applied.

> Remediation update: all 36 findings in this report were addressed in the
> subsequent implementation pass. Regression coverage was added in
> `test_bug_regressions.py`; the full offline suite now contains 184 passing
> tests. The evidence below describes the original audited checkout and is
> intentionally retained as the before-fix record.

## Result and evidence

**36 findings** are listed below. P1 means data integrity, a blocked main workflow, or materially corrupted output; P2 means a functional defect with narrower impact or a workaround. These priorities describe the trigger stated in each finding, not how often it occurs.

- **174 existing tests passed**, with no failures, errors, or skips. Tests ran through `unittest` discovery using the existing Python 3.12 virtual environment, with `config.PROJECTS_DIR` redirected to temporary storage and socket connections blocked. Hugging Face/Transformers offline modes were enabled.
- All **67 tracked Python files parsed successfully**. `node --check static/js/app.js` passed. Every literal JavaScript DOM ID referenced exists in the template; handler existence and API contracts still fail as described below.
- Additional isolated probes exercised real state persistence, Flask routes, mocked model streams, fault injection, and JavaScript functions in a Node VM with a minimal DOM. **R** means the defective behavior was reproduced offline. **S** means the finding was established by tracing the implementation; the described full runtime scenario was not executed.
- Source references use the line numbers in the audited checkout. The only repository addition from this audit is this report. Existing application source, settings, and story data were not edited.

The report does not claim that every possible bug has been found. Existing tests are mostly component tests; their success does not validate the browser/API workflows.

## P1 — data integrity and blocked workflows

### 01. Creating a duplicate title resets the existing project state — R

**Locations:** `app.py:836`, `pipeline/orchestrator.py:3807`, `memory/state_manager.py:729`.

Create a second project with the same normalized title, including titles that collide after punctuation removal. Creation does not check for an existing project, and `initialize()` replaces state with a blank template. The probe returned HTTP 200, reset the chapter counter to zero, and left the original chapter file in place. Subsequent generation can overwrite those files.

**Correction:** Reserve a unique project name atomically; return a conflict for an existing project. Make replacement a separate explicit operation.

### 02. Separate state managers overwrite each other's changes — R

**Locations:** `memory/state_manager.py:321`, `memory/state_manager.py:457`, `memory/state_manager.py:545`; new managers are constructed by API requests.

Load the same project through managers A and B. Save a new title through A, then add an event through B. B writes its cached full state and restores the old title. The lock is per instance, and `load()` does not reload an already cached state. This affects editing while a generation or manual session retains a manager, even without simultaneous writes.

**Correction:** Serialize mutations per project and reload/check the persisted version inside that transaction. Use unique temporary files as well; a shared `state.json.tmp` is unsafe across separate writers.

### 03. Project operations do not share a consistent busy guard — R/S

**Locations:** `app.py:1217`, `app.py:1310`, `app.py:1429`, `app.py:1582`, `app.py:919`, `app.py:1176`, `app.py:2145`.

With an active manual session, an automatic-generation request was accepted with HTTP 200 because it checks only `_active_pipelines`, not `_manual_sessions`. Scene generation and finish also separate their busy check from reservation, allowing concurrent requests through. State edits, chapter deletion, reset, and project deletion do not reject active work. These paths can race over the same state/chapter files or resurrect deleted data.

**Correction:** Use one project operation lock/reservation policy, claim it in the same critical section as validation, and apply it to all conflicting mutations. The auto/manual overlap was reproduced; threaded deletion and double-finish races were source-traced.

### 04. Resuming a missing chapter destroys state before validation — R

**Location:** `pipeline/orchestrator.py:3010`, especially pruning at `3035` before checking the chapter file.

Request resume of missing chapter 2 from a project whose state is at chapter 3. State and vector memory are pruned to chapter 1 before `FileNotFoundError` is raised. The probe confirmed the counter change, removed summaries, and vector-prune call despite resume failing.

**Correction:** Read and validate the target and rollback prerequisites before making any persistent change; commit the resume transition atomically.

### 05. Resuming an earlier chapter leaves later chapter files active — R

**Locations:** `pipeline/orchestrator.py:3010`, `pipeline/exporter.py:83`, `pipeline/gemini_combiner.py:757`.

Resume chapter 1 of a three-chapter project. The probe showed state rewound to chapter 0 while chapter 3 remained on disk. The chapter API, exporter, and combiner can still include those later files, while future generation will reach and overwrite their chapter numbers. State and published story text disagree immediately.

**Correction:** Define an explicit rewind/archive operation for the target and later chapters, and make readers/exporters respect the same committed chapter set. Preserve later drafts recoverably.

### 06. A failed chapter finalization leaves state committed and drops the session — R/S

**Locations:** `pipeline/orchestrator.py:3624`, `pipeline/orchestrator.py:4449`, `app.py:1597`.

Finalization advances summaries, chapter counters, scene counts, and premise progress before embedding and trace persistence finish. Injecting an embedding write failure left `current_chapter=3` and the scene count incremented despite the operation failing. The API's `finally` block removes the manual session even on failure. Auto finalization has the same ordering, so retry can advance past an incompletely committed chapter.

**Correction:** Stage the complete result and commit it transactionally, or provide durable recovery with idempotent finalization. Retain recoverable sessions after failures. State advancement was reproduced; API session cleanup is source-traced.

### 07. Editing prose does not update the memory used to write the next scene — R/S

**Locations:** `pipeline/orchestrator.py:4620`, `pipeline/orchestrator.py:3437`, `pipeline/orchestrator.py:3481`, `pipeline/orchestrator.py:3383`.

Editing a completed chapter rewrites only its Markdown file. The probe preserved `OLD SUMMARY` after replacing the prose with `NEW TEXT`, with no vector-store calls. Manual scene deletion/editing similarly changes text/WIP while leaving already-applied evolution events, relationships, and character changes behind. Future writing can follow events the user has removed.

**Correction:** Rebuild or invalidate affected derived memory and replay later state from a valid checkpoint. Chapter-edit staleness was reproduced; manual evolution staleness follows the traced mutation paths.

### 08. Reset and rewind retain dead-character state and stale entity records — R/S

**Locations:** `memory/state_manager.py:338`, `memory/state_manager.py:920`.

After marking a character dead, `reset_generated()` left both the character and entity status as `dead`. Pruning also does not rewind the entity registry or character lifecycle status; it removes generated characters without removing their entity records. A restarted story therefore carries facts from the discarded timeline.

**Correction:** Restore lifecycle and registry state from the retained timeline or original definitions, and remove discarded generated entities. Full-reset retention was reproduced; partial-prune behavior was source-traced.

### 09. Evolution changes character status without updating the authoritative registry — R

**Locations:** `memory/evolution_engine.py:445`, `memory/state_manager.py:476`, `memory/state_manager.py:627`, `agents/verifier.py:212`.

With an existing active registry entry, an evolution update marked Alice dead in `characters` while `get_entity_status('Alice')` still returned `active`. Backfill skips existing entries, and the verifier reads the registry first. This disables the intended deterministic resurrection check after a normal evolution update.

**Correction:** Update character and entity identity/status together through one canonical transition, including aliases and newly introduced characters.

### 10. Ordinary project maintenance requires a working generation model — R

**Locations:** `pipeline/orchestrator.py:191`, `pipeline/orchestrator.py:235`; API construction at `app.py:846`, `app.py:923`, `app.py:1168`, `app.py:2172`.

Project creation, state editing, chapter editing, and some exports construct the full orchestrator, which initializes/probes models before loading storage. An isolated state-edit request returned HTTP 500 solely because the selected GGUF file was absent. Cloud modes similarly gate maintenance on connectivity and provider availability.

**Correction:** Separate storage/maintenance services from model initialization; load providers only for operations that actually require inference.

### 11. Manual scene completion is never handled in the browser — R

**Locations:** `static/js/app.js:1144`, `static/js/app.js:1444`; producer at `app.py:1450`.

The server emits `manual_scene_done`, but `handleSSEEvent()` has no branch for it. After dispatching a successful completion in the Node probe, `manualIsGeneratingScene` remained true, the Generate button remained disabled, and completed-scene count stayed zero. Tokens also go to automatic-generator cards rather than `manualStreamOutput`.

**Correction:** Add a manual event lifecycle that renders streamed/final prose, synchronizes session state, and restores controls on success, failure, cancellation, and disconnect.

### 12. Manual Stop and Edit buttons call nonexistent functions — R

**Locations:** `templates/index.html:635`, `static/js/app.js:1426`.

The template calls `stopManualScene()` and dynamically rendered scene cards call `editManualScene(index)`. Neither function exists in the loaded script. Handler discovery and VM lookup confirmed both are undefined; clicking them raises a reference error.

**Correction:** Implement the handlers against the existing cancel-scene and scene-update APIs and verify the complete UI actions.

### 13. The vision UI does not match the registered API — R/S

**Locations:** `static/js/app.js:2058`, `static/js/app.js:2114`, `static/js/app.js:2164`; `vision/router.py:13`, `vision/router.py:110`.

The UI requests `/vision/status`, `/vision/analyze`, and `/vision/chat`. The blueprint exposes `/api/vision/status`, `/api/vision/analyze`, and `/api/vision/chat/start` plus `/api/vision/chat/message`. The tested analyze/chat URLs returned 404. The UI also sends `extra_prompt` instead of `prompt_extra`, reads incompatible result fields, and never creates or submits a chat session ID.

**Correction:** Align routes, request fields, response envelopes, and chat-session lifecycle together. Prefix correction alone will not repair the feature.

### 14. Premise generation discards the user's outline — R

**Locations:** `static/js/app.js:959`, `app.py:939`.

The browser submits `{idea_text: text}`, while the server reads `idea`. A mocked model received a prompt that omitted the unique outline supplied in the request. The premise tools also do not submit the project's characters/setting/themes, and the endpoints do not load those fields from the named project.

**Correction:** Use a single request contract and load canonical project context on the server, with explicit overrides if needed.

### 15. Generate Whole Story actually selects the polish path — R/S

**Locations:** `static/js/app.js:1867`, `app.py:1750`, `app.py:1810`.

The browser sends `whole_story: true`; the server branches on `mode == 'whole'` and otherwise defaults to polish. The captured browser request confirms the mismatch. For a project without chapters this also prevents the intended whole-story path that tolerates an empty combined input.

**Correction:** Submit and validate `mode: 'whole'`, and test fresh-project as well as existing-chapter behavior.

### 16. Gemini streaming strips word boundaries and can leak reasoning text — R/S

**Locations:** `models/gemini_model.py:225`, `models/base.py:55`.

Every stream chunk is passed independently through `_strip_reasoning()`, which ends with `.strip()`. The mocked chunks `Hello ` and `world.` became `Helloworld.`. Reasoning blocks spanning chunks also cannot be removed correctly by a per-chunk whole-string regex.

**Correction:** Apply the shared stateful stream filter to the complete chunk iterator and preserve whitespace. Whitespace corruption was reproduced; split reasoning handling was source-traced.

### 17. The launcher kills unrelated processes on port 5000 — S

**Location:** `start.sh:5`.

Startup unconditionally sends a termination signal to every PID returned by `lsof -t -i:5000`, without checking whether it belongs to Story Teller. Launching the app can stop an unrelated service or connection using that port.

**Correction:** Track and verify this application's process, or report a port conflict. Do not kill arbitrary port users. The launcher was intentionally not executed during the audit.

## P2 — functional and conditional defects

### 18. Manual session Reset only changes the browser — R

**Location:** `static/js/app.js:1561`; server conflict at `app.py:1376`.

The reset callback sends no request and leaves `_manual_sessions[name]` alive. The Node probe captured zero requests. Starting another manual chapter consequently encounters the server's existing-session conflict, and any active worker is unaffected.

**Correction:** Provide an explicit server-side session-abandon operation with a clear draft-retention policy; update the UI after it succeeds.

### 19. Asynchronous jobs are reported as successfully completed when merely accepted — R/S

**Locations:** `static/js/app.js:1542`, `static/js/app.js:1829`, `static/js/app.js:1856`; responses at `app.py:1610`, `app.py:1864`.

Manual finish returns `finishing`; combine/whole-story returns `started`. The browser immediately announces successful storage/completion and hides progress. It never subscribes to `/combine/stream`. A later job failure is therefore hidden, and versions are refreshed before the result exists. With typed scenes only, manual finish may have no SSE connection either.

**Correction:** Treat the POST as acknowledgement, track the job, and announce completion only on its terminal success event. Browser request handling and server response contracts were checked; real model jobs were not run.

### 20. Saved polished prose is read from the wrong response field — R

**Locations:** `static/js/app.js:1816`, `app.py:1998`.

The API returns `revised`, while the browser reads `polished`. Given a real-shaped version response, the VM probe left the polished panel empty and displayed `1 words`.

**Correction:** Use `revised` consistently and calculate empty word counts correctly; clear stale panels when switching versions.

### 21. Download ignores the selected combined-story version — R

**Location:** `static/js/app.js:1900`; API supports `suffix` at `app.py:2089`.

With an archived version selected, the browser still opened the download URL without a suffix, so the server selects `latest`. Renaming latest can leave the selected archive downloadable only through a manually constructed URL.

**Correction:** Include the encoded selected suffix for original, polished, and analysis downloads.

### 22. Disconnecting an SSE consumer removes the active producer's queue — R

**Locations:** `app.py:1689`, `app.py:1703`, `app.py:1883`, `static/js/app.js:1126`.

Closing a generation response removed its queue from `_event_queues`; reconnect returned `No active generation`. The worker can still hold and write to the original queue. Multiple viewers also consume competing entries from a single queue rather than receive a broadcast. The combine stream uses the same cleanup pattern.

**Correction:** Separate job lifetime from subscription lifetime; support per-subscriber delivery or replayable event IDs. Consumer cleanup must not remove another job's queue. Disconnect loss was reproduced; multi-viewer behavior was source-traced.

### 23. Batch generation UI finishes early and reuses scene IDs across chapters — R/S

**Locations:** `static/js/app.js:1163`, `static/js/app.js:1211`.

A `chapter_complete` event immediately clears `isGenerating` and hides Cancel, although later chapters in the batch are still running. This was reproduced. Scene cards are keyed only by scene number, so chapter 2 scene 1 collides with chapter 1 scene 1; creation is skipped and subsequent tokens can append to the wrong card. A cancelled `done` event is also announced as successful completion.

**Correction:** Track job, chapter, and scene separately. End the job only on `done`, inspect terminal status, and key cards by chapter plus scene.

### 24. WIP chapters are mislabeled, and WIP-only chapters cannot be read — R

**Locations:** `app.py:1079`, `app.py:1142`.

Generation progressively writes both Markdown and WIP. The list endpoint treats any Markdown chapter as completed and skips its WIP entry. The probe confirmed this. A WIP-only chapter was listed but its read endpoint returned 404, despite the orchestrator having WIP-reading support.

**Correction:** Determine completion from committed state/WIP, and use a unified chapter reader that can recover checkpoint text.

### 25. Removing characters or clearing traits in Edit Story does not persist — R

**Locations:** `static/js/app.js:768`, `static/js/app.js:794`, `memory/state_manager.py:1078`.

The UI submits the remaining character map, but the API applies an additive merge. Omitted characters remain, and traits are unioned rather than replaced. Submitting only Alice with an empty traits list left Bob and Alice's old `brave` trait in state.

**Correction:** Separate user replacement/deletion semantics from incremental AI updates, and keep the entity registry consistent with explicit edits.

### 26. Tension, motif, and legend updates mutate discarded snapshots — R/S

**Locations:** `memory/evolution_engine.py:316`, `memory/evolution_engine.py:329`, `memory/evolution_engine.py:338`, `memory/state_manager.py:558`.

These helpers mutate the dictionary returned by `state_manager.state`, which is a deep copy. The following `save()` writes the unchanged internal state. A real evolution pass with mocked extraction reported `tension_recorded=true`, but persisted no tension curve. Motif and legend calls have the same snapshot mistake.

**Correction:** Persist each update through a StateManager transition, or commit the modified snapshot with version checking. Tension loss was reproduced; the other two paths were source-traced.

### 27. Some updates marked pending review are committed as facts — R/S

**Locations:** `memory/evolution_engine.py:250`, `memory/evolution_engine.py:445`, `memory/evolution_engine.py:629`, `memory/evolution_engine.py:665`.

Only emotions and relationships pass through the confidence split. A pending-review entity update still marked Alice dead, and a pending-review death event was saved without its pending flag. Arc updates have the same missing gate.

**Correction:** Apply the same review policy to every extracted update category and persist pending updates separately. Entity/event commits were reproduced; arc handling was source-traced.

### 28. Exposed TPM and routing settings are saved but not applied to runtime — R/S

**Locations:** `app.py:102`, `app.py:384`, `app.py:426`.

`GROQ_TPM_LIMIT`, its window/margin/reserve/pacing options, `GROQ_PROACTIVE_ROTATION`, and `HYBRID_ROUTING` are accepted settings but omitted from runtime assignment. Requesting a TPM limit of 6001 left the effective value at 6000. Environment strings change, but providers read the already-imported `config` attributes.

**Correction:** Use one authoritative setting-to-config mapping and verify persisted versus effective values. The limit mismatch was reproduced; the sibling omissions were source-traced.

### 29. Unrelated settings saves silently remove additional Groq rotation keys — R

**Location:** `app.py:391`.

`_apply_runtime_settings()` uses an empty string when `GROQ_API_KEYS` is omitted, rebuilding the list from the primary key only. This occurs with partial updates and with redacted secrets skipped by the settings endpoint. A two-key probe retained only one after changing an unrelated setting.

**Correction:** Preserve existing keys unless the key-list setting is explicitly changed or cleared.

### 30. The main CLI ignores the configured backend selection — S

**Locations:** `main.py:141`, `main.py:170`, `pipeline/orchestrator.py:165`, `config.py:58`.

CLI commands construct `PipelineOrchestrator` without backend arguments; its default is local. The web app interprets `BACKEND_MODE`, but the CLI does not. In a Groq/Gemini/OpenRouter configuration with cloud-writer mode false, `main.py generate` still selects local initialization and can fail for a missing GGUF.

**Correction:** Share backend resolution between CLI and web, including selected model IDs, and test CLI startup for every backend with mocked providers.

### 31. Explicit temperature zero is replaced with the default — R/S

**Locations:** `models/openrouter_model.py:155`, `models/openrouter_model.py:302`, `models/groq_model.py:331`, `models/groq_model.py:531`.

These adapters use `temperature or default`. The mocked OpenRouter request received 0.8 when the caller requested 0. Both synchronous and streaming paths in Groq/OpenRouter contain the same expression.

**Correction:** Use an explicit `is None` check. OpenRouter synchronous behavior was reproduced; matching paths were source-traced.

### 32. Loading stats before a different-dimension embedder creates an incompatible index — R

**Locations:** `memory/vector_store.py:89`, `memory/vector_store.py:123`, `memory/vector_store.py:165`, `memory/vector_store.py:305`.

For a project configured with a 768-dimensional embedding model, loading stats first creates a 384-dimensional empty index. Loading the embedder later changes `_dimension` but not that index. The isolated fake-encoder probe failed with `AssertionError`, with index dimension 384 and model dimension 768.

**Correction:** Resolve embedding metadata before index creation, validate loaded index compatibility, and recreate only an empty incompatible index or explicitly rebuild stored text. This is conditional on changing the default embedding model.

### 33. Lexical fallback and transformer vectors are mixed without compatibility tracking — S

**Locations:** `memory/vector_store.py:117`, `memory/vector_store.py:140`, `memory/vector_store.py:165`, `memory/vector_store.py:476`.

If the transformer is unavailable, persisted vectors use lexical hashing. After a restart with the transformer available, the same index is reused for transformer queries/additions. Equal dimensions conceal incompatible vector spaces, producing meaningless similarity scores. The inverse availability change has the same problem.

**Correction:** Persist an embedding backend/model/version fingerprint with each index and rebuild from stored texts before changing embedding spaces. No real embedding download or migration was attempted.

### 34. Advertised authenticated and HTTPS upstream proxies are unsupported — R/S

**Locations:** `proxy_rotator.py:21`, `proxy_rotator.py:58`, `proxy_rotator.py:64`, `proxy_rotator.py:102`.

Parsing accepts credentials and `https://`, but the `Upstream` record retains only host/port. Generated requests contain no configured proxy authorization, and all connections are plain TCP. The mocked request omitted authorization; an HTTPS URL without a port resolved to port 80. A TLS proxy will not understand the resulting plaintext request.

**Correction:** Preserve scheme and credentials, use TLS with certificate validation for HTTPS upstreams, choose the correct default port, and attach proxy authentication. Alternatively reject unsupported URL forms honestly.

### 35. Proxy drops request bodies with lowercase Content-Length — R

**Location:** `proxy_rotator.py:126`.

Headers are retained with their original casing, then body length is retrieved through `dict(headers).get('Content-Length', '0')`. A request with `content-length: 7` forwarded the header but omitted the `PAYLOAD` body in the mocked upstream probe, causing an upstream wait or malformed request.

**Correction:** Normalize header names for lookup and implement/reject unsupported body framing explicitly, including chunked requests.

### 36. Malformed image input escapes the route's error handling — R

**Locations:** `vision/router.py:43`, `vision/router.py:58`, `vision/router.py:119`.

Base64 decoding happens before the `try` block. Posting `image_base64: 'a'` returned HTTP 500 rather than a structured client error. Chat start repeats the same decoding pattern. Clients expecting JSON receive an HTML error response in normal Flask error handling.

**Correction:** Validate and decode inside the guarded request-parsing path, reject invalid input with JSON 400, and apply the same behavior to analyze and chat start.

## Coverage limits and next validation

Inspected the Flask/UI contracts and major generation/persistence flows, plus model adapters, memory/evolution modules, CLI entry points, exporter/world-bible/combiner paths, vision routes/providers, and proxy handling. Passing offline component tests covered additional planner, verifier, quality, memory, and CLI behavior. This was not a proof of every branch in every module.

Not executed: paid/cloud requests, actual GGUF inference, embedding downloads, production startup, visual browser interaction, external proxy connections, or destructive operations against user projects. Provider model-catalog validity, current SDK/provider acceptance, real cancellation latency, long-story quality, production connection limits, and browser rendering require follow-up live validation. No remote exploitability claim is made from this audit.

Recommended repair order: protect state and project operations (01–09), decouple maintenance from models (10), repair browser/API contracts and streaming (11–16, 18–25), then address memory/settings/adapters/proxy defects. Add regression tests for the reproduced failures as part of each fix; the current 174-test suite misses these integration paths.
